A practical guide for the checked-out project

Go from .ax source to a running program.

AX is an experimental, indentation-sensitive language with a native compiler and a C++ runtime. Start with a short program, then explore tensor operations, AI runtime kernels, native builds, and the tools included in this repository.

Build AX ↓ Explore AI runtime →
Experimental

This is not a complete 110-feature production language. The guide separates tested behavior from partial, prototype, or absent features.

01

Get ready

Build the compiler

Build from the repository root. The project uses CMake and C++20; the build includes the compiler, runtime, command-line tools, and test executables.

01

Operating system

Linux x86_64 or Linux ARM64. Native builds select the host architecture.

02

Toolchain

CMake 3.22+, a C compiler, a C++20 compiler, and Make or Ninja.

03

Build checks

The CMake configuration enables -Wall -Wextra.

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2

The build creates both build/ax and the compatibility command build/axc. To type ax without a path prefix, add the build directory to your current shell:

source scripts/ax-env.sh
ax --help

If an older build only has build/axc, the helper creates a build/ax link. This PATH change lasts for the current terminal session.

ARM64 build: run bash scripts/build_arm64.sh on a native Linux ARM64 machine. On x86_64 it stops with an explicit message; an x86_64 build does not verify ARM64.
02

First success

Write, compile, and run

Create hello.ax in the repository or a scratch folder:

fn main() -> i32:
    print("Hello from AX")
    return 0

Compile to an executable, then run it:

ax build hello.ax -o /tmp/hello
/tmp/hello

Or ask the compiler to compile and run in one step:

ax run hello.ax

fn main() -> i32:

Defines the program entry point and its integer exit status.

Four-space indentation

A colon begins a block. Indentation is part of the syntax style.

print(...)

Writes a scalar, string, or supported tensor value to standard output.

return 0

Ends the program successfully.

Try the included demo: ax build examples/compiled_demo.ax -o /tmp/ax-demo && /tmp/ax-demo prints 42.
03

Learn the source language

AX syntax you can use now

The best reference for the exact supported subset is the compiler plus the passing examples. AX currently has functions, typed locals, arithmetic and comparisons, conditionals, loops, tensor literals, and calls to runtime operations.

Typed values and expressions

fn main() -> i32:
    price: f32 = 19.0
    count: i32 = 2
    total = price * count
    print(total)
    return 0

Branches and loops

fn classify(value: f32) -> i32:
    if value > 0.0:
        print("positive")
    else:
        print("zero or negative")
    return 0

fn main() -> i32:
    for item in range(3):
        print(item)
    return 0

Other examples show while and parallel for. Exact typing, ownership rules, closures, and advanced syntax are not equivalent to a mature language; check a feature in a small source file before depending on it.

Tensor literals and shape checking

fn main() -> i32:
    values: Tensor[f32, 4] = tensor([1.0, 2.0, 3.0, 4.0])
    print(softmax(values))
    return 0

Check a file without linking using ax check file.ax. examples/bad_shape.ax intentionally contains an incompatible tensor operation, so it should be rejected.

Declarations are not proof of full language support. Struct, enum, trait, and macro-shaped declarations appear in the examples, but full trait dispatch, hygienic macro expansion, pattern matching, and advanced type features are not complete. The feature matrix records the status.
04

Use the AI pieces

AI and LLM runtime guide

AX has a small set of tensor operations callable from `.ax` and a broader collection of native C++ runtime APIs. The runtime components are useful for learning and experimentation; they do not yet combine into a complete model-training or model-serving stack.

STEP 1

Start with an AX tensor

Read and run the small examples before building a model.

ax run examples/softmax_demo.ax
STEP 2

Exercise runtime bindings

This example checks AX calls into several native inference kernels.

ax run examples/m2_runtime.ax
STEP 3

Inspect a backend path

Generate output and inspect it; generation alone does not run on accelerator hardware.

ax emit-ptx examples/cuda_kernel.ax

Run a real GPU kernel with @gpu

@gpu uses Vulkan compute and targets physical GPUs with a compatible Vulkan compute driver. Intel Arc was verified here; other GPUs require compatible drivers. Check the device, then build the kernel suite:

ax devices
ax check examples/gpu_ai_kernels.ax
ax build examples/gpu_ai_kernels.ax -o /tmp/ax-gpu-ai.axg
/tmp/ax-gpu-ai.axg
@gpu
fn scale_bias(values: Tensor[f32, 8]) -> Tensor[f32, 8]:
    return values * 2.0 + 1.0

The example runs a 16×16 shared-memory tiled matrix multiplication; row-wise softmax, RMSNorm, and layernorm reductions; multi-input arithmetic; fused SwiGLU; and ReLU, sigmoid, SiLU, and GELU kernels. Shader code compiles to SPIR-V and is embedded in the native executable. If no physical GPU exists, ax check and ax build report an error; GPU functions never silently run on CPU. Install a Vulkan driver plus glslc or glslangValidator.

If ax devices lists multiple GPUs, set AX_GPU_DEVICE=1 before compiling and running to select device index 1. Index 0 is the default.

Kernel limits: fixed positive tensor dimensions and f32 only; no dynamic shapes or automatic fusion between separate functions. AX reuses the Vulkan device and caches compiled pipelines, but still creates buffers and dispatch resources per call. CUDA, ROCm, and TPU output commands do not execute their kernels. Read the full GPU guide.

AX-callable tensor operations

Current examples exercise matmul, gemm, relu, softmax, layernorm, rmsnorm, rope, swiglu, geglu, gelu, silu, sigmoid, tanh, mse_loss, cross_entropy, and adamw. See examples/all_features.ax and examples/m2_runtime.ax for calls exercised by smoke tests.

Call a native AI kernel from C++

#include "runtime/core/ai_kernels.hpp"
#include <array>

int main() {
    const std::array<float, 4> input{1.0f, 2.0f, 3.0f, 4.0f};
    const auto output = ax::ai::rms_norm(input, 1, input.size());
    return output.size() == input.size() ? 0 : 1;
}

Link the CMake axrt target. This operation returns a new std::vector<float> owned by the caller.

Example: differentiate a scalar in C++

#include "runtime/core/autodiff.hpp"

int main() {
    ax::ai::DiffGraph graph(1);
    const auto x = graph.input(0);
    const auto y = graph.multiply(x, x);
    const auto gradient = graph.vjp({3.0}, y);
    // gradient[0] is 6.0
    return gradient[0] == 6.0 ? 0 : 1;
}

Link a C++ program to the CMake axrt target to use this API. The C++ unit tests exercise gradients against finite differences.

What AX AI does not yet include: a production LLM trainer/server, full model import, Python/PyTorch/NumPy bridge, speculative decoding, or a complete GPU inference/training stack. The stdlib/ directory contains category folders but not a complete importable `.ax` standard library.

Native runtime beyond tensors

Game, concurrency, and systems APIs

Several engine-style components are implemented as C++ runtime APIs. AX source examples for game, coroutine, and distribution features are mostly smoke/syntax samples; use the runtime headers and the C++ tests to study the actual implemented behavior.

AreaStart withWhat is implementedBoundary
Entity/component storageruntime/core/ecs.hppDense SoA storage for one fixed component signature, generation-checked entities, typed queries, and parallel_forNo dynamic archetype migration or compiler query scheduler
Physics helpersruntime/core/physics.hppSpring energy/gradient and triangle BVH build/raycastNot the requested full collision suite or NEON acceleration
Deterministic mathruntime/core/fixed.hppQ16.16/Q32.32 fixed-point arithmetic, integer square root, CORDIC sine/cosineNot exposed as a native `.ax` type
Render planningruntime/core/rendergraph.hppPass dependency ordering, cycle checks, barriers, and transient lifetime alias planningNo full Vulkan command-buffer or shader pipeline integration
Task scoperuntime/coro/coro.hppCooperative stop-token cancellation and child joiningNo compiler-enforced coroutine lifetime system
Channels and actorsruntime/coro/channel.hpp, runtime/coro/actor.hppBounded SPSC/MPMC queues, queue polling select, bounded actor mailboxNot a complete async networking or supervision framework
Local distributed runtimeruntime/dist/dist.hpp, runtime/dist/checkpoint.hppSeparate-process localhost all-reduce and master checkpoint pathNo elastic recovery, distributed trainer, or WAN peer mesh

Small C++ ECS example

#include "runtime/core/ecs.hpp"

struct Position { float x = 0.0f; };
struct Velocity { float x = 0.0f; };

int main() {
    ax::game::ArchetypeWorld<Position, Velocity> world;
    world.create(Position{0.0f}, Velocity{1.0f});
    auto [positions, velocities] = world.query<Position, Velocity>();
    ax::game::parallel_for(world.size(), 2, [&](std::size_t begin, std::size_t end) {
        for (std::size_t i = begin; i < end; ++i) positions[i].x += velocities[i].x;
    });
    return 0;
}

Use the CMake axrt target for runtime components implemented in `.cpp`; template-only APIs such as the ECS also need C++20 and thread linking. `examples/game_loop.ax`, `examples/coro.ax`, and `examples/distribute_demo.ax` are introductory smoke examples, not full engine loops or distributed-training programs.

06

Generate native and accelerator output

Backends: compile, emit, execute

Ordinary ax build compiles for the host CPU. A source file with supported @gpu functions instead embeds Vulkan compute kernels and requires a physical GPU at compile time.

HOST NATIVE

x86_64 / ARM64

ax build chooses the host. Linux ARM64 verification requires an ARM64 machine.

EMITTER

AArch64 assembly

ax emit-asm file.ax prints ARM64 assembly even on x86_64.

GPU EXECUTION

Vulkan @gpu

Tiled GEMM, row reductions, activations, and elementwise kernels compile to SPIR-V.

EMITTER

PTX / ROCm / TPU

emit-ptx, emit-rocm, and emit-stablehlo emit output for external runtimes; they are not launched by AX.

EMITTER

StableHLO / SPIR-V

StableHLO emits MLIR text. emit-spirv compiles a supported @gpu kernel; without one, its old fallback module remains minimal.

ax emit-ir examples/m2_runtime.ax > /tmp/model.mir
ax emit-asm examples/matmul.ax > /tmp/matmul-arm64.s
ax emit-ptx examples/cuda_kernel.ax > /tmp/kernel.ptx
ax emit-rocm examples/rocm_kernel.ax > /tmp/kernel.hip
ax emit-stablehlo examples/tpu_kernel.ax > /tmp/kernel.mlir
ax emit-spirv examples/gpu_ai_kernels.ax -o /tmp/gpu.spv
Key distinction: only the documented @gpu subset runs through Vulkan. PTX/ROCm/StableHLO generation does not launch CUDA/AMD/TPU code.

08

Connect AX to another program

C ABI and embedding

Build a shared library

AX functions except main are emitted as exports. The compiler writes a `.so` and a generated header next to it:

ax build examples/shared_math.ax --shared -o /tmp/libshared_math.so

The public ABI uses AxVal*. Compile a C consumer like the one exercised by tests/test_shared_cli.sh:

#include "ax_runtime.h"
#include "libshared_math.h"

int main(void) {
    AxVal* result = ax_scale(ax_scalar(21.0), ax_scalar(2.0));
    ax_print(result);
    return 0;
}
cc -I/path/to/project/include -I/tmp caller.c \
  -L/tmp -lshared_math -Wl,-rpath,/tmp -o /tmp/caller
/tmp/caller

Current constraints: shared `.so` output, at most six `AxVal*` parameters per exported function, and no general scalar C ABI conversion or static `.a` export mode. The public `AxVal` ABI has no release function yet, so treat repeated allocations from a long-lived host as experimental.

Embed compiler services in C

Include include/ax_embed.h and link the CMake target ax_embed. The static library provides source checking plus MIR/assembly emission, not an in-process JIT:

#include "ax_embed.h"
#include <stdio.h>

int main(void) {
    AxEmbedBuffer output = {0};
    const char* source = "fn main() -> i32:\n    return 0\n";
    int result = ax_embed_emit_ir(source, "example.ax", &output);
    if (result == 0) puts(output.data);
    ax_embed_buffer_release(&output);
    return result;
}

Return values are 0 success, 1 source diagnostics, and 2 API/internal error. Always release output buffers with ax_embed_buffer_release.

Explore the rest of the toolchain

Developer tools and editor support

axfmt

Normalizes indentation and whitespace. It is a lightweight formatter, so inspect changes before accepting them.

build/axfmt file.ax -o formatted.ax

axedit

Native terminal editor with AX keyword colors, file-local completions, function signatures, and live type hints.

ax edit examples/hello.ax

axlint

Runs simple heuristic checks such as line length and likely unused variables.

build/axlint file.ax

axlsp

A limited JSON-RPC-over-stdio prototype with static completion and hover responses. Semantic diagnostics, go-to-definition, and benchmark code lenses are not complete.

axdbg

A command-loop prototype. It does not execute AX programs instruction by instruction or record/replay runtime events.

There is no JIT REPL, compiled notebook engine, Python-to-AX migrator, auto-documentation generator, flamegraph profiler, or deterministic record/replay debugger in this checkout.

axedit is the built-in terminal editor. editors/vscode/ contains file-extension/syntax metadata, and the Neovim snippets are starter material; those external editor integrations are not polished IDE extensions today.

12

Solve common setup problems

Troubleshooting

ax: command not found

From the repository root, run source scripts/ax-env.sh. The helper adds build/ to this shell's PATH and can create an alias from an existing build/axc. If both compiler binaries are missing, build with CMake first.

ax: compiler not found

The helper cannot find a built compiler. Run cmake -S . -B build -DCMAKE_BUILD_TYPE=Release followed by cmake --build build --parallel 2. If you used a custom build directory, set AX_BUILD_DIR before sourcing the helper.

@gpu reports no Vulkan GPU

Run ax devices. CMake must find Vulkan development files, the system needs a physical GPU driver that exposes a compute queue, and kernel compilation needs glslc or glslangValidator. CPU-only llvmpipe is deliberately rejected. AX does not silently fall back to CPU for an @gpu function.

AArch64 assembly reports invalid instructions on x86

ax emit-asm emits ARM64 assembly. Use ax build to compile for the current host, or assemble the emitted file with an AArch64 toolchain.

A tensor expression is rejected

Run ax check file.ax first. Verify tensor ranks and dimensions in each operation. examples/bad_shape.ax is intentionally invalid and is expected to fail.

Why does an accelerator example run on CPU?

The native executable build uses the host backend. An emitter command can produce PTX, ROCm, StableHLO, or SPIR-V output, but a separate hardware/runtime integration is needed to execute accelerator kernels.
